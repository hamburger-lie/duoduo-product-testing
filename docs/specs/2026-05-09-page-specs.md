# 页面规格 · 4 张关键页（文字版）

> 配套：`2026-05-09-soul-binding-design.md` v5
> 用途：作为 UI 视觉稿绘制依据 + 前端工程实施依据
> 范围：P1（新建）/ P2（角色登场）/ P3（对话）/ P4（历史）

## 0. 通用规格（适用所有页面）

### 0.1 基底
- 平台：微信小程序原生（或 Taro/uni-app，等工程阶段定）
- 屏幕基准：iPhone 14（390×844 pt），单位 rpx
- 顶部胶囊按钮：保留原生
- 底部 Tab：`调研` / `我的`（首期 2 个）

### 0.2 视觉令牌（占位，待视觉稿确认）
| Token | 候选值 |
|---|---|
| 主题色 | 雾紫 `#7B6FA8` 或 灰青 `#5A8A8C` |
| 背景 | `#F7F7F8` |
| 卡片底 | `#FFFFFF` |
| 文字主 | `#1F1F2E` |
| 文字次 | `#888A9B` |
| 思考流文字 | `#9BA0B5` 灰斜体 |
| 字号 | 标题 36rpx / 正文 28rpx / 辅助 22rpx |
| 圆角 | 卡片 24rpx / 气泡 36rpx / 按钮 40rpx |
| 间距 | 标准 24rpx / 紧凑 16rpx |

### 0.3 通用组件
- Loading：转圈 + "稍等..."
- Toast：底部 2s 自动消失
- 错误弹层：标题 + 描述 + "知道了" 按钮

## 1. P1 · 新建调研页

### 1.1 入口与出口
- **入口**：首页 → 「+ 新调研」按钮
- **出口**：左上返回 / 提交成功跳 P2

### 1.2 布局示意
```
┌─────────────────────────────────┐
│ ◀     新调研           ⓘ        │  顶导
├─────────────────────────────────┤
│                                 │
│ 上传产品图（1-3 张）             │
│ ┌──────┐ ┌──────┐ ┌──────┐    │
│ │ 📷+  │ │ (空) │ │ (空) │    │  虚线槽位
│ └──────┘ └──────┘ └──────┘    │
│                                 │
│ 描述这款产品（≥20 字）           │
│ ┌─────────────────────────────┐ │
│ │ 这是一款__，主打__，希望了解__│ │
│ │                          0/300│ │
│ └─────────────────────────────┘ │
│                                 │
│ 调研主题（可选）                 │
│ ┌─────────────────────────────┐ │
│ │ 例如：想测包装吸引力          │ │
│ └─────────────────────────────┘ │
│                                 │
├─────────────────────────────────┤
│  ┌───────────────────────────┐  │
│  │     开始调研  →           │  │  主按钮（吸底）
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

### 1.3 元素清单
| 区域 | 元素 | 状态 | 文案 / 规则 |
|---|---|---|---|
| 顶导 | 标题 | - | 「新调研」 |
| 顶导 | ⓘ 帮助 | 点击 → 弹层 | 简介玩法（**不出现"灵魂附着"**字眼） |
| 上传区 | 3 个图片槽 | 空 / 上传中 / 已上传 / 失败 | 至少 1 张，最多 3 张 |
| 单图槽 | 点击空槽 | - | 唤起 `wx.chooseImage` |
| 单图槽 | 已传缩略图 | 长按 | 弹"删除"操作菜单 |
| 上传区 | 提示文字 | - | "仅产品图 / 品牌图。非产品图将被拒绝" |
| 描述区 | 多行输入 | 默认 / 聚焦 / 不足 | 占位文字「这是一款__，主打__，希望了解__」<br>实时计数 `0/300`，<20 字时计数变红 |
| 主题区 | 单行输入 | 可空 | 占位「例如：想测包装吸引力」 |
| 底栏 | 主按钮 | 禁用 / 可点 / 加载中 | 禁用条件：图片<1 或 描述<20<br>点击 → 调 `api.startResearch()` |

### 1.4 交互流
1. 用户点空图槽 → 调 `api.uploadImage()` → 失败 toast / 成功显缩略图
2. 用户填描述 → 实时校验字数；图片 + 描述满足 → 主按钮可点
3. 点「开始调研」→ 按钮 loading → 调 `api.startResearch({ images, description, topic })`
4. 成功 → `wx.redirectTo` 跳 P2，传 `sessionId`
5. 失败错误码处理：
   - `INVALID_IMAGE` / `NOT_PRODUCT_IMAGE` → 弹"图片格式不符，请上传产品图"
   - `DESCRIPTION_TOO_SHORT` → 描述输入框边框变红（理论上前端已拦截）
   - `QUOTA_EXCEEDED` → 弹"今日额度已用完"

## 2. P2 · 角色登场页

### 2.1 入口与出口
- **入口**：P1 提交成功后 `redirectTo`，参数携 `sessionId`
- **出口**：动效结束（约 3-5 秒）后自动 `redirectTo` → P3

### 2.2 布局示意
```
┌─────────────────────────────────┐
│ ◀                                │  顶导（仅返回）
├─────────────────────────────────┤
│                                 │
│                                 │
│        正在召集消费者...         │  标题（淡入）
│                                 │
│      ┌───┐    ┌───┐    ┌───┐   │
│      │👤│   │👤│   │👤│       │  3 头像（依次淡入）
│      └───┘    └───┘    └───┘   │
│      小芸     王姐     朵朵      │  名字（跟随头像）
│      白领     全职妈妈 大学生    │  职业
│                                 │
│         她们准备好了             │  最终态文案（动效结束）
│                                 │
└─────────────────────────────────┘
```

### 2.3 元素清单
| 区域 | 元素 | 行为 |
|---|---|---|
| 主区 | 标题 | "正在召集消费者..." → "她们准备好了"（4s 切换） |
| 主区 | 3 头像槽 | 占位剪影 → 第 1 个淡入(0s) → 第 2 个(0.6s) → 第 3 个(1.2s) |
| 主区 | 3 组名字+职业 | 跟随对应头像淡入，名字大字 / 职业小字 |
| 全局 | 总时长 | 约 3 秒动效 + 1 秒停留 → 自动跳 P3 |

### 2.4 异常处理
- 接口失败：底部出现"召集失败 [重试]"按钮
- 用户中途返回：丢弃当前 session，无后续保留

### 2.5 数据来源
- 直接读取 P1 已返回的 `personas` 数据，**本页不再调任何接口**

### 3.3 元素清单（详细）
| 区域 | 元素 | 状态 | 行为 |
|---|---|---|---|
| 顶导 | 标题 | - | "调研中" / "调研已完成" |
| 顶导 | 3 头像 | - | 点 → 弹角色卡 modal（姓名+职业+一句自我介绍） |
| 顶导 | ⋯ 菜单 | - | 选项："结束调研" / "导出对话" |
| 话题条 | 编号 | - | "💬 系统话题 · X/9" |
| 话题条 | 文本 | - | 当前话题原文 |
| 消息流 | 话题分隔条 | - | 每个话题前显示，淡蓝灰 |
| 消息流 | 角色身份行 | - | 头像 + 名字 + "·" + 职业 |
| 消息流 | 思考流气泡 | 灰斜体 / 半透明 / 💭 | 流式逐字出现 |
| 消息流 | 说话流气泡 | 白底圆角 + 头像 | 长按 → 弹"引用追问 / 复制 / 取消" |
| 消息流 | 用户追问气泡 | 主题色右对齐 | 含引用块 + "@朵朵" 等指向 |
| 消息流 | 报告卡片 | 9 话题完成后出现 | 标题"调研报告" + 6 段 + 展开/收起 + 复制 + 导出 |
| 输入区 | 引用条 | 追问态 | × 关闭 → 取消引用 |
| 输入区 | 文本框 | - | 占位"提一个问题..." |
| 输入区 | 发送按钮 | 禁用 / 启用 | 输入>1 字启用 |

### 3.4 状态机
| 状态 | 说明 | 触发跳转 |
|---|---|---|
| `loading` | 加载历史/初始化 | 数据就绪 → `topic_running` |
| `topic_running` | 话题进行中，3 角色依次输出 | 3 人完成 → 下一话题 / 全部完成 → `report_pending` |
| `awaiting_user` | （可选）每话题后留一秒供追问 | 用户输入或超时 → 下一话题 |
| `report_pending` | 9 话题完成，报告生成中 | 报告就绪 → `report_ready` |
| `report_ready` | 报告卡片就位 | 终态 |
| `terminated` | 用户提前结束 | 直接走报告生成 |
| `read_only` | 从历史进入的已完成调研 | 不能再发问；可导出 |

### 3.5 关键交互细节

**3.5.1 角色发言节奏**
1. 系统抛话题（话题条更新）
2. 角色 1 身份行出现 → 思考流流式出字（800ms-1500ms）→ 说话流流式出字（1500ms-3000ms）
3. 角色 1 完整完成后停 800ms → 角色 2 同样流程
4. 三人完成 → 短暂过渡 → 下一话题

**3.5.2 引用追问**
1. 长按任意"说话流"气泡 → 弹底部 ActionSheet：「引用并追问 / 复制 / 取消」
2. 选"引用并追问" → 输入框上方出现引用条（含被引用文字 + × 关闭）
3. 系统在输入框预填"@朵朵 "（自动 @ 该角色）
4. 用户输入文本 → 发送 → 仅该角色回应（思考+说话）
5. 追问完成 → 系统继续走原话题序列

**3.5.3 报告呈现（不打断节奏）**
1. 9 话题走完 → 出现过渡条："调研已完成 · 正在整理报告..."（3-8s 假等待）
2. 报告卡片浮出（轻微缩放+淡入），位于消息流末尾
3. 卡片操作：展开/收起 / 复制全文 / 导出（首期仅复制）

**3.5.4 结束调研**
- 菜单"结束调研" → 弹确认："确定提前结束吗？已有内容会保留并生成报告"
- 确认 → 跳过剩余话题 → 直接 `report_pending` → 报告生成

## 5. 前端 API 契约（services/api.ts 业务方法清单）

为支撑上述 4 张页面，前端 api 层应至少提供：

```typescript
// ─── 上传 ───
api.uploadImage(file: File): Promise<{ url: string; key: string }>;

// ─── 调研主流程 ───
api.startResearch(input: {
  images: { url: string }[];
  description: string;
  topic?: string;
}): Promise<{
  sessionId: string;
  personas: Persona[];
  topics: string[];
}>;

api.fetchTranscript(sessionId: string): Promise<TranscriptResponse>;

api.subscribeDialogueEvents(
  sessionId: string,
  onEvent: (e: DialogueEvent) => void,
): () => void;  // 返回 unsubscribe；mock 时用 setTimeout 链模拟流式

api.askFollowup(input: {
  sessionId: string;
  quotedMessageId: string;
  targetPersonaId: string;
  content: string;
}): Promise<void>;  // 真实结果通过 subscribeDialogueEvents 推送

api.terminateResearch(sessionId: string): Promise<void>;

// ─── 历史 ───
api.listSessions(input?: {
  cursor?: string;
  limit?: number;
  keyword?: string;
}): Promise<{ items: SessionSummary[]; next_cursor: string | null; has_more: boolean }>;

api.getSession(sessionId: string): Promise<SessionDetail>;

// ─── 报告 ───
api.fetchReport(sessionId: string): Promise<ReportContent>;
```

> Phase A：以上方法全部以 Mock 实现，数据来自本地 JSON
> Phase B：替换为真实 Stub 后端调用
> Phase C：Adapter 内部映射到 `API_CONTRACT.md` 完整接口组合，**业务页面零改动**
