# 需求文档：聊天视图跟随内容滚动

**创建日期**：2026-05-16
**适用页面**：`miniprogram/pages/chat/chat`（调研对话页 / 单角色追问页）
**优先级**：P0（影响核心体验）

---

## 1. 背景

测品官小程序的「调研对话」页面会以打字机方式逐字渲染 AI 测品官的回答，并支持后续用户追问的流式输出（SSE）。当内容超出可视区域时，视图必须自动滚动到底部，让用户始终能看到最新输出。

线上现状：
- 旧实现用 `scroll-into-view` + 双锚点交替（`msg-sa` / `msg-sb`），真机表现不稳定，打字机过程中页面常常停在中部不动；
- 用户已多次反馈"滚动条不会跟着输出更新"。

## 2. 用户故事

- **U1（被动观看）**：作为产品经理，我打开"调研对话"页面后，希望像看真实聊天一样，新内容自动从底部冒出来；我不应该频繁手动下拉才能看到正在生成的文字。
- **U2（主动回看）**：作为用户，当我向上滑动查看较早的内容时，页面不应该把我"拽"回底部；只有当我滑回底部时，自动跟随才恢复。
- **U3（主动发问）**：作为用户，发送追问后，输入框上方的我的消息和角色回复必须立刻出现在可视区域底部。
- **U4（页面加载）**：作为用户，进入有历史消息的对话页时，进来就应该看到最新一条，而不是从顶部开始翻。

## 3. 功能需求

### FR-1 自动追随

| 触发场景 | 期望行为 |
|---------|---------|
| 角色逐字打字（typewriter） | 每追加一段文字，视图同步滚到底部 |
| 用户追问流式 SSE 输出 | 每收到一个 `delta` / `think_delta`，视图同步滚到底部 |
| 加载完成（onLoad / loadConversation） | 进入页面时立刻定位到底部 |
| 用户点击「发送」 | 新建的 user 气泡 + 占位 speak 气泡出现后立即滚到底部 |
| 滚动到底部状态下，新增气泡（typeNextPersona 启动下一个角色） | 自动跟随 |

### FR-2 智能暂停

| 触发场景 | 期望行为 |
|---------|---------|
| 用户在 scroll-view 上向下拖动（查看较早内容） | 停止自动追随，保持用户当前查看位置 |
| 用户重新把视图拖到底部（触发 `bindscrolltolower`） | 恢复自动追随 |

### FR-3 性能与体验

- 自动滚动期间不应出现明显抖动、跳变、回弹；
- 打字机 50ms tick 频率下，CPU 占用、setData 频率需控制在真机可承受范围；
- 在 iOS / Android、微信开发者工具 / 真机均需一致表现。

## 4. 非功能性需求

- **稳定性**：必须避免使用易受 WeChat 渲染时序影响的方案（如直接依赖元素 ID 在 DOM 中的可见性判断）。
- **可维护性**：滚动控制逻辑集中在 1-2 个方法内，便于后续在「单角色追问页」复用。
- **兼容性**：基础库 ≥ 2.14.0（项目当前最低支持）。

## 5. 验收标准

- [ ] AC-1：在「调研对话」页观察 3 位测品官完整打字过程，无任何手动操作时滚动条始终贴底，最后一行始终可见。
- [ ] AC-2：测试过程中主动向上滑动 200rpx 后，10 秒内视图不被自动拉回底部。
- [ ] AC-3：滑回底部后，下一次新内容生成时，自动跟随恢复。
- [ ] AC-4：发送追问后，新气泡 200ms 内出现在可视区域底部。
- [ ] AC-5：刷新页面（含历史会话），首屏直接显示最新一条消息。
- [ ] AC-6：iOS 16+ / Android 10+ 真机、微信 8.0+ 表现一致。

## 6. 失败案例（已观察到的回归点）

- **F-1**：`scroll-into-view` 的目标元素若已在视口内，WeChat 不会重新触发滚动 → 流式输出新增内容把锚点顶出去后，视图不动。
- **F-2**：`scroll-top` 在 `scroll-with-animation="false"` 下，设置相同值不触发滚动 → 两次 setData 值不变就被合并丢弃。
- **F-3**：Page 实例错误调用 `this.createSelectorQuery()`（Component 才有），导致测量结果永远为 `undefined`。
- **F-4**：`bindtouchmove` 在用户每次点击屏幕时都误判为上滑 → 自动追随被错误打断。

## 7. 验证清单（开发自查）

- [ ] 选择器查询使用 `wx.createSelectorQuery().in(this)`；
- [ ] `scroll-top` 值在每次更新时包含至少 1px 抖动以确保 prop diff；
- [ ] `_atBottom` 切换有明确的"向下拖动阈值"（建议 ≥ 8px），避免普通点击触发；
- [ ] `_atBottom` 通过 `bindscrolltolower` 恢复，不依赖 scroll-view 内部状态；
- [ ] 卸载时清理所有 setInterval / setTimeout。
