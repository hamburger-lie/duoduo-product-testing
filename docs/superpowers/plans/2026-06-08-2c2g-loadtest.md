# 2C2G Local Load Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a local Docker Compose profile that simulates a 2 core / 2 GB server and make database pool timeout explicit for production-like load testing.

**Architecture:** Keep load-test simulation isolated in a dedicated Compose override file. Add `DB_POOL_TIMEOUT` to the central settings object and pass it directly to SQLAlchemy's async engine. Make production database connection budgets explicit so worker count and pool count cannot accidentally exceed the small-server budget.

**Tech Stack:** FastAPI, Pydantic Settings, SQLAlchemy async engine, Docker Compose, Pytest, Uvicorn, Postgres, Redis.

---

## File Structure

- Modify `app/core/config.py`: define `db_pool_timeout` with env alias `DB_POOL_TIMEOUT`.
- Modify `app/db/session.py`: pass `pool_timeout=settings.db_pool_timeout` into `create_async_engine`.
- Modify `.env.example`: document local optional `DB_POOL_TIMEOUT`.
- Modify `.env.production.example`: replace oversized production pool defaults with 2C2G-safe values and add timeout.
- Modify `docker-compose.yml`: pass explicit DB pool env vars to API, worker, and beat services.
- Modify `deploy/docker-compose.prod.yml`: pass explicit DB pool env vars and set API workers to 2 for 2C2G default.
- Create `docker-compose.loadtest-2c2g.yml`: local-only resource-constrained load-test override.
- Modify `tests/test_production_config.py`: assert the new setting parses correctly.

    pool_recycle=settings.db_pool_recycle,

## Task 3: Add 2C2G Local Load-Test Compose Override

**Files:**
- Create: `docker-compose.loadtest-2c2g.yml`

- [ ] **Step 1: Create the override file**

Create `docker-compose.loadtest-2c2g.yml` with:

```yaml
services:
  postgres:
    deploy:
      resources:
        limits:
          cpus: "0.60"
          memory: 640M

  redis:
    command: redis-server --appendonly yes --appendfsync everysec --maxmemory 128mb --maxmemory-policy allkeys-lru
    deploy:
      resources:
        limits:
          cpus: "0.10"
          memory: 160M

  qdrant:
    cpus: "0.10"
    mem_limit: 256M
    deploy:
      resources:
        limits:
          cpus: "0.10"
          memory: 256M

  api:
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      qdrant:
        condition: service_started
    environment:
      DB_POOL_SIZE: ${DB_POOL_SIZE:-8}
      DB_MAX_OVERFLOW: ${DB_MAX_OVERFLOW:-4}
      DB_POOL_TIMEOUT: ${DB_POOL_TIMEOUT:-2}
      DB_POOL_RECYCLE: ${DB_POOL_RECYCLE:-1800}
    command: uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2 --access-log
    deploy:
      resources:
        limits:
          cpus: "1.20"
          memory: 850M

  worker:
    environment:
      DB_POOL_SIZE: ${WORKER_DB_POOL_SIZE:-4}
      DB_MAX_OVERFLOW: ${WORKER_DB_MAX_OVERFLOW:-2}
      DB_POOL_TIMEOUT: ${DB_POOL_TIMEOUT:-2}
      DB_POOL_RECYCLE: ${DB_POOL_RECYCLE:-1800}
    command: uv run celery -A app.tasks.celery_app.celery_app worker -Q evaluations -l info -c 1
    deploy:
      resources:
        limits:
          cpus: "0.30"
          memory: 256M

  beat:
    environment:
      DB_POOL_SIZE: ${WORKER_DB_POOL_SIZE:-4}
      DB_MAX_OVERFLOW: ${WORKER_DB_MAX_OVERFLOW:-2}
      DB_POOL_TIMEOUT: ${DB_POOL_TIMEOUT:-2}
      DB_POOL_RECYCLE: ${DB_POOL_RECYCLE:-1800}
    deploy:
      resources:
        limits:
          cpus: "0.10"
          memory: 128M
```

- [ ] **Step 2: Validate merged load-test config**

Run: `docker compose -f docker-compose.yml -f docker-compose.loadtest-2c2g.yml --profile api config`

Expected: Compose prints normalized config without YAML errors. API command shows `--workers 2`; API environment shows `DB_POOL_TIMEOUT: "2"`.
