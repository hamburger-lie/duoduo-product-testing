# 赢家锚定评分（Winner-Anchored Scoring）设计方案

- 日期：2026-06-18
- 状态：方案待复核（brainstorming 产出，未进入实现计划）
- 背景痛点：当前角色填问卷打分**系统性偏低**——已经很畅销的产品评分不高；新品天然冷读偏低，低分成为推广阻力，打击用户信任。
- 目标：让分数**对标真实市场表现**。已上市老品（有数据）要"准"；新品按"赢家的感觉"打分并给出可信的成功归因。

---

## 1. 现状诊断（为什么会偏低）

经逐行核对评分链路，偏低有四个来源：

1. **提示词把分数锚死在"我个人买不买"**，且明写"3 分不是默认安全分，观望→更接近 2 分"（`backend/app/ai/prompts/persona_answer.j2:191-198`），系统性把 1-5 均分往 3 以下压。
2. **挑剔型角色（is_critical）双重扣分**：推荐时强制 ≥20% 占比（`backend/app/services/persona_service.py:225` `_ensure_critical_balance`，floor 见 `:227`，仅在 `recommend_personas` 生效），且对这些角色"给 4-5 分要更充分理由"（`persona_answer.j2:277`）。聚合阶段对所有角色等权（`report_service.py:911` `_calc_overall_intent`，从不读 is_critical），所以挑剔角色只通过"占比 + 个体低分"双重拉低均值。
3. **角色只能冷读产品卡片**——"这款已经很畅销"这一现实信号（真实销量/口碑/品牌势能）根本没进模型输入，无从奖励"已被市场验证"。
4. **工程瑕疵**：雷达分在同一字段里混用 1-5（规则兜底 `_calc_dimensions_radar:953`）与 0-100（LLM/语义 `dimension_score.j2`），降级时雷达看起来灾难性低；NPS 恒为 0（`report_service.py:931`）。

> 结论：第 1-3 条是"分数性格/缺现实锚"，第 4 条是 bug。单纯调高分会摧毁工具的诊断价值，必须用"赢家锚定 + 校准"而非拍脑袋抬分。

---

## 2. 目标与非目标

**目标**
- 已上市且有市场数据的产品：显示分与真实战绩高度对齐（"老品很准"）。
- 新品：基于"赢家长什么样"给出预测分 + **为什么会火的拆解** + 信心度，建立用户信任。
- 分数分布被一组"已知结果产品"（验证集）钉住，可度量、可验证。

**非目标 / 明确排除**
- 不做"沾边赢家就高分"的橡皮图章（见 §4 闸门）。
- 不在本方案内解决数据采集来源（单列数据线，假设赢家数据已就绪）。
- 新品分数本质是**预测**，无法在测的当下被现实验证——只能靠在历史赢家上校准好引擎并赌其泛化。文档对此保持诚实，前端以信心度呈现。

---

## 3. 总体架构：三层

在现有"纯消费者模拟"引擎上叠一层"赢家锚定"，成为三层。**核心原则：第一层喂养第二层，而非各打一分再平均。**

### 第一层 · 消费者模拟（现有，去偏后）
角色照常模拟真实人群的需求反应，但其产出**降级为"证据"**而非直接定分：哪些痛点被戳中、价格抗拒在哪、社会认同够不够，作为输入喂给第二层的成功因子。

附带的去偏（S0，因为 sim 不再直接定分，破坏力已降一档，做最小必要修正）：
- 去掉"3 不是默认安全分→压向 2"的强制下压，回归中性。
- 缓解 is_critical 在提示词层的"4-5 需更充分理由"为"保持该角色应有的挑剔，但不额外压分"；保留 is_critical 的占比（真实人群本就有挑剔者），但**取消聚合层的隐性双重惩罚**。
- 修雷达 1-5/0-100 串字段；NPS 恒 0 字段废弃或重定义。

### 第二层 · 赢家锚定（新增，方案核心）
两个**离线产物** + 一个**测时动作**：

- **成功标尺（Success Rubric，离线蒸馏，分品类）**：把赢家集合按品类喂模型，提炼反复出现的成功要素 + 权重。轴采用**混合**：以现有 10 维度为底座（复用问卷证据），再补若干问卷未覆盖、从赢家中蒸馏出的成功要素（如"视觉冲击/货架表现""社会认同强度""价格带卡位""卖点记忆点"）。
- **赢家库（Winner Store，离线建，分品类）**：每个赢家 = 产品属性（与新品同一特征空间）＋ 真实战绩 ＋ "为什么赢"短胶囊 ＋ 向量（供相似检索）。
- **测时**：检索最像的 K 个同品类赢家 → 用该品类成功标尺给本品逐因子打分（结合产品属性 + 第一层证据）→ 组织"它像谁、在哪些赢家因子上强/弱"的叙事。

### 第三层 · 输出（改造现有报告）
最终分 = 标尺校准分（老品有真实数据则向真实战绩对齐兜底）＋ 成功拆解（为什么火/会火）＋ 信心度 ＋ "像哪些爆品"。

## 4. 评分机制（承重墙）

### 4.1 计算流程
1. **逐因子打分**：每个成功因子 0-100，由模型结合产品属性 + 第一层角色证据，对照该品类因子定义判分。
2. **加权求和** → 原始成功分 `S_raw`（0-100）。权重来自标尺蒸馏，并在验证集上调优。
3. **校准映射** `f()` → 显示分。在"赢家+扑街"验证集上拟合一个**单调映射**（默认等距回归 isotonic；简化兜底为分位分段线性：扑街档→0-40、中间→40-70、赢家档→70-100），使已知爆品聚到高分段、扑街聚到低分段。**这就是"老品很准"的机械来源。**
4. **老品真实数据兜底对齐**：显示分 = `(1-α)·f(S_raw) + α·realOutcomeScore`。
   - `realOutcomeScore` = 品类内真实信号（销量分位、评分×评价量）映射到 0-100。
   - `α` 随数据强度（评价量、时效）增大；新品 `α = 0`。

### 4.2 防"沾边就高分"的闸门（必须钉死）
> **相似度只驱动「信心度 + 它像谁的叙事」，绝不直接抬分。分数永远由「本品在成功因子上的真实得分」决定。**

新品哪怕长得像爆品，若成功因子（成分说服力、痛点契合…）实际不行，加权分照样低；相似度高只让叙事更具体、信心度更高。既给新品"按老品感觉"的信任背书，又不变橡皮图章。

### 4.3 信心度模型
`confidence = g(最近赢家相似度, 因子证据覆盖率, 角色样本量, 品类赢家密度)`。新品信心度天然更低，且**显式呈现**，不藏。

### 4.4 品类冷启动兜底
某品类赢家样本不足（默认阈值 < 8）时：回退到全局标尺 + 放宽相似检索范围，**封顶信心度**，并标注"类比样本不足"。避免小样本品类拟合出虚假高/低分。

---

## 5. 校准与验证

- **验证集** = 赢家（畅销）+ 扑街（卖不动）两类已知结果产品，每个带真实战绩档位。
- **指标**：
  1. 预测显示分 vs 真实销量档的**秩相关（Spearman）**达标；
  2. 已知爆品**落进高分段**比例、已知扑街落进低分段比例。
- **调参对象**：成功因子权重 + 校准映射 `f()`。
- 验证集同时承担"回归测试"——后续改提示词/标尺，跑一遍看分布是否仍对齐。

## 6. 对现有系统的集成点

- **数据模型**：新增 `WinnerStore`（赢家库，分品类，含属性/战绩/胶囊/向量）、`SuccessRubric`（分品类因子+权重+校准映射参数）。
- **离线任务**：标尺蒸馏 job、赢家入库 job（embedding 生成）。
- **测时链路**：在报告生成处（`report_service.py` 的 `get_or_create_report` / `generate_dimension_analysis` 一带）插入"锚定检索 + 校准打分 + 解释"步骤。
- **报告 schema 新增字段**（`backend/app/schemas/report.py`）：
  - `calibrated_overall_score`（0-100）
  - `success_factor_breakdown[]`（每因子分 + 强弱）
  - `nearest_winners[]`（像谁 + 相似度）
  - `confidence`
  - `why_it_wins` / `gaps_vs_winners`（叙事）
  - 保留现有 1-5 intent 作为内部证据/次级信号。
- **去偏 S0**：`persona_answer.j2` 提示词最小改动 + 聚合层取消 is_critical 隐性双重惩罚 + 修雷达字段/NPS。

## 7. 分解为可实现子项目（每个单独 spec → plan → 实现）

- **S0 · 去偏 + 修 bug**：不依赖数据，第一层地基。小。
- **S1 · 赢家库 + 数据接入**：建模存储 + embedding；数据来源单列（本方案假设就绪）。
- **S2 · 成功标尺蒸馏**：离线，从赢家分品类提炼因子 + 权重。
- **S3 · 锚定检索 + 校准打分/解释 + 报告集成 + 校准验证**：测时主链路。

依赖关系：S0 可独立先行；S2、S3 依赖 S1 的数据；S3 依赖 S2 的标尺。

---

## 8. 待确认 / 风险

- **数据来源未定**（单列数据线）：美妆电商销量/口碑源、正负样本如何标注"畅销/扑街"的统一口径。
- **负样本（扑街）稀缺**：可能只有正样本，导致校准偏高，需要补偿（如用同类目长尾低销量近似负样本）。
- **特征空间一致性**：赢家必须与新品用同一套产品属性描述，否则"像不像"不成立。
- **校准映射过拟合**：验证集小时 isotonic 可能过拟合，需留出 holdout 或用更稳的分段映射。
- **品类划分粒度**：分品类已定；价格带是否再细分留待数据量到位后评估。
